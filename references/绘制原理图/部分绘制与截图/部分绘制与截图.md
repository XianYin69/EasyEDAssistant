## 绘制部分原理图

1. **用户技术细节拍板**：页数、模块拆分、位号与 net 命名、图纸信息栏先与用户确认（属设计决策，不清空拍板）；**每页元件数 ≤150**（官方：原理图引擎非新引擎，超出显著卡顿，拆页优先于密排）；同时可先摊字符画蓝图（`./tmp/plan/<工程>-sch-layout.md`）评审。
2. **绘制（批量优先）**：按模块执行 `sch compose` 生成计划、`sch apply` 落图——**一个模块一次队列**，禁止逐器件多轮编辑器往返（破坏性操作先 `--dry-run` 预览）；用户装有官方批量放置扩展 `eext-batch-place-components`（查 tool-probe 插件清单）时，可用 CSV 坐标（表头带单位）批量落位初始器件，之后照常 compose/autoconnect；连线用 `sch autoconnect`（`--pin/--kind/--net` 或 `--spec` 批次），已连目标网的脚自动跳过。
3. **每步对账**：每步 apply 后回读 `sch connectivity` / `sch list`，核对 pin→net、NC、器件身份与图面一致，再做下一步。

## 截图与清理

1. **逐个部分两张图 + 即时归档**：一个部分绘制完成后，用官方导图 `sch export-image`（文档渲染，不依赖视口刷新，无需 stale 检测）分别截取该部分局部图与整张全图；两张图立即归档到 `./tmp/sch/`（命名 `sch-<部件号>-<局部|全图>-<时间戳>.png`），作为交付图片候选，不随快照清理删除。
2. **快照滚动**：`./tmp/snapshots/` 只是工作区滚动快照；每张新截图生成前删除最旧一张，使目录只保留最近 3 张（命名加 `sch-` 前缀，与 PCB 截图分开计数）；验收与交付一律读 `./tmp/sch/` 归档图，不依赖快照。
3. **与命令行纠错交叉**：截图（呈现层）与每步回读、门禁输出（数据层）互验，任一发现错误即进入纠错。

## 检查原理图是否美观和正确（截图 + 命令行双通道纠错）

1. **正确性（数据层）**：逐页 `sch gate --strict`（`layout-lint → check → bridge-check → SDK DRC`）与 `sch check`，pin→net 与黄金表一致、无悬空脚、无孤儿桩。
2. **美观（呈现层）**：先看归档截图（视觉判读：文字压线或压框、模块框是否完整包含内容、阅读顺序是否 Z 字、同排器件方向是否一致、跨模块是否用 netport），再跑 `python3 scripts/visual-qa.py`（退出码 0 通过 / 2 WARN / 3 阻断）自动评估；数据层结论始终为权威。
3. **双通道互验**：截图与命令行输出**都过** → 进入「全部是否绘制完成」判定；任一发现错误 → 回到「绘制部分原理图」修改后重画并重截、重跑命令行检查。

## 判据与动机

- 绘制期用**截图 + 命令行双通道纠错**：数据回读/门禁是权威，截图提供视觉终检，两者互验、缺一不可。
- 每部分归档图存 `./tmp/sch/` 不随快照清理——交付时作为技术手册插图来源（`交付与清理/交付文档`）。
- 批次连线后必跑 `sch check` 兜「叠加 marker」；`sch connect` 不幂等，不盲重发。
- 快照只保最近 3 张是回溯折中：工作快照不累积，正式图一律走 `./tmp/sch/` 归档。
