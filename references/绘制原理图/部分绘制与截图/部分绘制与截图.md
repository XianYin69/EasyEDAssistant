# EasyEDAssistant Reference：绘制原理图 — 部分绘制与截图

> 本文件是「绘制原理图」第 4～6 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 绘制部分原理图

1. **用户技术细节拍板**：页数、模块拆分、位号与 net 命名、图纸信息栏先与用户确认（属设计决策，不清空拍板）；同时可先摊字符画蓝图（`./tmp/plan/<工程>-sch-layout.md`）评审。
2. **绘制**：按模块执行 `sch compose` 生成计划、`sch apply` 落图（破坏性操作先 `--dry-run` 预览）；连线用 `sch autoconnect`（`--pin/--kind/--net` 或 `--spec` 批次），已连目标网的脚自动跳过。
3. **每步对账**：每步 apply 后回读 `sch connectivity` / `sch list`，核对 pin→net、NC、器件身份与图面一致，再做下一步。

## 截图与清理

1. **逐个部分两张图**：一个部分绘制完成后，分别截取该部分局部图与整张全图（原理图用官方导图 `sch export-image`，文档渲染不依赖视口刷新）。
2. **次数判定**：统计 `./tmp/snapshots/` 中原理图截图次数；大于 3 次 → 丢弃三次前截取的截图（保留最近 3 张关键快照作回溯），否则保留现有截图。
3. **命名与状态**：截图存 `./tmp/snapshots/step-<索引>-<时间戳>.png`；与上帧比对标记 fresh/stale，stale 视为 canvas-freeze，重取后再判定。

## 检查原理图是否美观和正确

1. **正确性（数据层）**：逐页 `sch gate --strict`（`layout-lint → check → bridge-check → SDK DRC`）与 `sch check`，pin→net 与黄金表一致、无悬空脚、无孤儿桩。
2. **美观（呈现层）**：看文字压线或压框、模块框是否完整包含内容、阅读顺序是否 Z 字、同排器件方向是否一致、跨模块是否用 netport。
3. **判定**：正确且美观 → 进入「全部是否绘制完成」判定；不美观或不正确 → 回到「绘制部分原理图」修改后重画并重截。

## 判据与动机

- 数据是权威、截图只做视觉终检；两者冲突时以回读数据为准并把 stale 标为阻断项。
- 批次连线后必跑 `sch check` 兜「叠加 marker」；`sch connect` 不幂等，不盲重发。
- 截图数量上限是磁盘与回溯的折中：保留最近 3 张即可复盘，不累积无限制图面。
