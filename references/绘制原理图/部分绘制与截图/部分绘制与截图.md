## 绘制部分原理图

1. **用户技术细节拍板**：页数、模块拆分、位号与 net 命名、图纸信息栏先与用户确认（属设计决策，不清空拍板）；**每页元件数 ≤150**（官方：原理图引擎非新引擎，超出显著卡顿，拆页优先于密排）；同时可先摊字符画蓝图（`./tmp/plan/<工程>-sch-layout.md`）评审。
2. **绘制（逐件落位、逐件截图纠错）**：连线等批量操作走 `sch autoconnect --spec` 批次与 `sch apply` 队列，但**器件落位按件推进**（`sch compose` 出计划后逐件落位）。
   - **截图硬门**：每落位/移动/修改一个器件必须**当次**运行 `python <SKILL_DIR>/scripts/visual-qa.py --schematic --project <工程> --doc <页> --artifacts-dir ./tmp/snapshots`（内部完成 `sch export-image --format png` 导图、器件 bbox 对 `sch sheet-geometry` 图纸边界的越界核验、压入 hard keepout（标题栏禁区）核验与数据回读）。
   - **通过判据**：**退出码 0 且本次落位产出新的 `sch-` 截图产物**——两者缺一即**该件未完成，禁止落位下一个**。
   - **失败处置**：退出 3（越界/缺图）当场回移/删除重画并重跑；同一件重试 ≤2 次仍失败 → 命中中断点暂停并如实报告，不得跳过继续画。
   - **禁止**：整批落位后统一补截、以「稍后补」跳过、以批量落位为由只跑一次核验代表整批（用官方 `eext-batch-place-components` CSV 批量落位时，落位后仍须**逐件**跑上述核验再进连线）。
3. **每步对账**：每步 apply 后跑 `python <SKILL_DIR>/scripts/sch-verify.py --project <工程> [--doc <页>]`——一次聚合 `sch gate --strict --json`、`sch connectivity --all-pages`、`sch list --all-pages --include-device-identity --include-pins`、`sch sheet-geometry`（JSON 落 `./tmp/sch/verify-*.json`，退出码 0 才做下一步），核对 pin→net、NC、器件身份与图面一致；单条命令细节先查 [`../../嘉立创EDA指令索引/原理图指令/原理图指令.md`](../../嘉立创EDA指令索引/原理图指令/原理图指令.md) 再 `--help` 确认参数。

## 截图与清理

1. **验证图（逐件）**：逐件纠错的截图即上一步 `visual-qa.py` 的导图产物（路径记在报告 `schematic.screenshot.path`）；脚本自动落 `./tmp/snapshots/` 并盖 `sch-` 前缀、滚动删到最近 3 张（与 PCB 前缀分开计数），**Agent 无需手动清理**；验证图只作纠错，不作交付；脚本对「未产出新图」判阻断（exit 3），杜绝静默不截图。
2. **归档图（逐部分）**：一个部分全部核验通过后，截该部分局部图与整张全图归档到 `./tmp/sch/`（命名 `sch-<部件号>-<局部|全图>-<时间戳>.png`），作为交付图片候选，不随快照清理删除。
3. **与命令行纠错交叉**：逐件截图（呈现层）与每步回读、门禁输出（数据层）互验，任一发现错误即回修该器件再继续。

## 检查原理图是否美观和正确（截图 + 命令行双通道纠错）

1. **正确性（数据层）**：`python <SKILL_DIR>/scripts/sch-verify.py --project <工程>`（内含逐页 `sch gate --strict` 四联：`layout-lint → check → bridge-check → SDK DRC`），pin→net 与黄金表一致、无悬空脚、无孤儿桩；退出码非 0 即阻断。
2. **美观（呈现层）**：先看归档截图（视觉判读：文字压线或压框、模块框是否完整包含内容、阅读顺序是否 Z 字、同排器件方向是否一致、跨模块是否用 netport——这些属目测项，`visual-qa.py` 不自动判读，须人工看归档图并结合用户验收），再跑 `python <SKILL_DIR>/scripts/visual-qa.py --schematic --project <工程> --doc <页>`（退出码 0 通过 / 2 WARN / 3 阻断）自动评估间距/重叠/出框；数据层结论始终为权威。
3. **双通道互验**：截图与命令行输出**都过** → 进入「全部是否绘制完成」判定；任一发现错误 → 回到「绘制部分原理图」修改后重画并重截、重跑命令行检查。**同一部分互验反复最多 3 轮**；满 3 轮仍不过即停止自动重试，按 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md) 摊牌（多为判据冲突或环境问题，不是再画一遍能解决的）。

## 判据与动机

- **逐件落位、逐件截图**是用户拍板的防越界手段：画到图纸外面必须当场发现、当场回移，不等整页画完再补救。
- 绘制期纠错走双通道：数据回读/门禁是权威，逐件截图提供视觉终检，两者互验、缺一不可。
- 每部分归档图存 `./tmp/sch/` 不随快照清理——交付时作为技术手册插图来源（`交付与清理/交付文档`）。
- 批次连线后必跑 `sch check` 兜「叠加 marker」；`sch connect` 不幂等，不盲重发。
- 验证图滚动 3 张、归档图逐部分留存：前者供即时纠错回溯，后者供交付，两轨不互替。
