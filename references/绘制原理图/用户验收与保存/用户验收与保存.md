# EasyEDAssistant Reference：绘制原理图 — 用户验收与保存

> 本文件是「绘制原理图」第 8 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 步骤

1. **询问用户是否接受原理图**：把 `./tmp/sch/` 归档的全图与各部分局部图、命令行门禁结果（`sch gate --strict` 的 pass/fail/blocked）一并摊给用户，明确询问是否接受。
2. **用户接受**：核对 `./tmp/sch/` 归档图片齐全（每部分局部 + 整页全图）；显式执行 `sch save` 并确认 `saved:true`；归档图片即交付期技术手册的插图来源，不得再随快照清理删除。
3. **用户不接受**：询问用户具体修改处（指出是哪一页、哪个模块、哪个器件或连接），记录后回到 [`../部分绘制与截图/部分绘制与截图.md`](../部分绘制与截图/部分绘制与截图.md) 修改并重绘重截。
4. **重跑检查**：任何修改后旧的门禁与对账结论失效，必须重跑 `sch gate --strict` 与 pin→net 对账，再回到本步骤询问用户。

## 保存纪律

- 用户接受前不把当前图面保存为交付基线；未保存的改动不得当作已交付。
- 归档图须为 `sch export-image` 官方导图（文档渲染，无需 stale 检测），导出后核对文件确实落位 `./tmp/sch/`。
- 保存与导图结果记录到交付报告：修改范围、门禁结果、已保存页面、归档图片清单、未解决问题。

## 判据与动机

- 验收是用户决策，不由 Agent 代拍板；`pass` 也不等于用户接受。
- `blocked` 表示检查未完成（环境问题），不得写成通过，须先修环境再复核。
- 修改后重跑检查是必要条件：几何或选型变更会让既有结论失效。
