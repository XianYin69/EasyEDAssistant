# EasyEDAssistant Reference：元件检查

> 本文件是「元件检查」步骤的总索引（自然语言）。触发时机：检查方案及敲定，成本及预算检查之后。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言；分支细则见各子文件。

## 流程

按方案元件清单逐个元件执行，全部元件通过后才算「元件检查通过」。

1. **联网查询元件技术手册**（见 [`查询技术手册/查询技术手册.md`](查询技术手册/查询技术手册.md)）：查到有效手册 → 第 2 步；查不到 → 第 3 步。
2. **检查当前元件封装**（见 [`封装与引脚检查/封装与引脚检查.md`](封装与引脚检查/封装与引脚检查.md)）：封装及引脚定义有问题 → 第 3 步；无问题 → 标记「单个元件检查通过」并建立元件与技术手册的所有者关系，该元件结束。
3. **询问用户是否需要建立新元件**（见 [`新建元件与替代方案/新建元件与替代方案.md`](新建元件与替代方案/新建元件与替代方案.md)）：同意 → 标记「建立新元件」并回到第 2 步检查新元件封装；不同意 → 第 4 步。
4. **询问用户是否需要使用替代方案**（同子文件）：同意 → 中断并处理设计问题（见 [`../处理设计问题/处理设计问题.md`](../处理设计问题/处理设计问题.md)），处理后回到被中断步骤；不同意 → 第 5 步。
5. **请求用户发送技术手册**（同子文件）：用户提供且手册有效 → 回到第 2 步重新检查封装；未提供或无效 → 中断并处理设计问题（见 [`../处理设计问题/处理设计问题.md`](../处理设计问题/处理设计问题.md)）。

## 判据与动机

- 每个元件必须有可追溯的手册来源（MPN、手册 URL、版本、页码）；无手册不得标记通过。
- 封装或引脚定义与手册不符即判不合格，只有「建立新元件」「改用替代方案」「用户补交有效手册」三条出路，不得静默通过。
- 中断与恢复遵循 [`../中断恢复/中断恢复.md`](../中断恢复/中断恢复.md)：等待期间不落笔，处理后从被中断点继续，不重跑已通过的元件。
- 手册与检索结果属证据链，不静默合并进硬编码判据，结论须经用户拍板。
