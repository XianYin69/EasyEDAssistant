# EasyEDAssistant Reference：元件检查 — 新建元件与替代方案

> 本文件是「元件检查」第 3～5 步的分支细则（自然语言）：手册查不到，或现有封装与引脚有问题时进入。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 步骤

1. **询问用户是否需要建立新元件**：
   - 用户同意 → 标记「建立新元件」，走下方「建立新元件（双通道验证）」节；通过后回到总索引第 2 步「检查当前元件封装」核对新元件。同一元件最多 2 次新建尝试；第 2 次仍不合格时不再自动新建，转入第 2 步询问替代方案并由用户决定。
   - 用户不同意 → 进入第 2 步。
2. **询问用户是否需要使用替代方案**：
   - 用户同意 → 发起「中断并处理设计问题请求」（见 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md)），处理后按 [`../../中断恢复/中断恢复.md`](../../中断恢复/中断恢复.md) 回到被中断的步骤。
   - 用户不同意 → 进入第 3 步。
3. **请求用户发送技术手册**：明确告知缺哪些信息（封装图、引脚表、电气参数）并请用户提供。
4. **校验用户手册**：
   - 已提供且有效（含封装与引脚定义、版本可辨、与器件型号一致）→ 回到总索引第 2 步「检查当前元件封装」。
   - 未提供或无效（型号不符、只有选型页、无引脚定义）→ 发起「中断并处理设计问题请求」（见 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md)），按中断恢复返回。

## 建立新元件（命令行 + 试放截图双通道验证）

命令条目见 [`../../嘉立创EDA指令索引/器件库与块/器件库与块.md`](../../嘉立创EDA指令索引/器件库与块/器件库与块.md)，参数以 `--help`/`easyeda actions` 为准。

1. **命令行建立**：先 `blocks search` 查可复用块；无则 `lib symbol create`→`build`（轮廓与引脚按手册原理图）、`lib footprint create`→`build`（焊盘形状/编号/间距按手册封装图；官方件不可改，先 `lib footprint copy` 到可写库再 build），最后 `lib device build`/`create` 组装绑定。
2. **数据层验证**：create 自带回读验证；再 `lib footprint get` / `lib symbol get` 逐项对照手册封装图与引脚表——焊盘数、编号、尺寸、丝印层，任一不符回 `build` 重做，不接受「差不多」。
3. **呈现层验证（试放截图）**：新建临时页（`sch page-new`）/临时板（`pcb new-board`）→ `sch place` / `pcb add-component` 试放一件 → `sch export-image` / `pcb snapshot`（stale 切前台重取至 fresh）→ 跑 `python <SKILL_DIR>/scripts/visual-qa.py --schematic --project <工程> --doc <临时页> --artifacts-dir ./tmp/snapshots` 与截图目检（引脚编号朝向、丝印可读、本体对照手册图）。
4. **判定与清理**：双通道任一不过 = 不算建立完成，回对应 build 修正后重验；通过后删除试放件与临时文档（`sch prim-delete`/`page-delete`），验证截图归档 `./tmp/sch/` 并在检查结论登记路径，或整页 `tmp-` 前缀留档不交付。

## 判据与动机

- 三条出路都必须落到「有可核对的手册来源」，不允许在无手册的情况下推进选型。
- 中断等待期间保持暂停态、不落笔；不替用户默认选择建立新元件或替代方案。
- 用户拒绝全部出路时不静默通过，按中断协议记录原因并交用户拍板。
