# EasyEDAssistant Reference：元件检查 — 新建元件与替代方案

> 本文件是「元件检查」第 3～5 步的分支细则（自然语言）：手册查不到，或现有封装与引脚有问题时进入。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 步骤

1. **询问用户是否需要建立新元件**：
   - 用户同意 → 标记「建立新元件」，走下方「建立新元件（双通道验证）」节；通过后回到总索引第 2 步「检查当前元件封装」核对新元件。同一元件最多 2 次新建尝试；第 2 次仍不合格时不再自动新建，转入第 2 步询问替代方案并由用户决定。
   - 用户不同意 → 进入第 2 步。
2. **询问用户是否需要使用替代方案**：
   - 用户同意 → 发起「中断并处理设计问题请求」（见 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md)），处理后按 [`../../中断恢复/中断恢复.md`](../../中断恢复/中断恢复.md) 回到被中断的步骤。
   - 用户不同意 → 进入第 3 步。
3. **请求用户发送技术手册**：明确告知缺哪些信息（封装图、引脚表、电气参数）并请用户提供。
4. **校验用户手册**：
   - 已提供且有效（含封装与引脚定义、版本可辨、与器件型号一致）→ 回到总索引第 2 步「检查当前元件封装」。
   - 未提供或无效（型号不符、只有选型页、无引脚定义）→ 发起「中断并处理设计问题请求」（见 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md)），按中断恢复返回。

## 建立新元件（建库前拍板门 → 命令行 + 试放截图双通道验证）

命令条目见 [`../../嘉立创EDA指令索引/器件库与块/器件库与块.md`](../../嘉立创EDA指令索引/器件库与块/器件库与块.md)，参数以 `--help`/`easyeda actions` 为准。

0. **建库前先向用户摊技术细节（P0）**：由 Agent 自绘新元件前，把「为什么必须新建、引脚功能与电气类型依据、符号划分思路、封装尺寸与命名」逐条向用户解释，每条带手册页码出处；未摊细、未拍板不得进入下方建立。
1. **独立元件图 + 引脚说明（建库材料）**：落 `./tmp/newpart/<型号>-newpart.md`——①**引脚说明表**（编号/名称/功能/电气类型/推荐符号引脚序号，逐行标手册页码，读不到的标「未核实」）；②**字符画原理图符号图**（box-drawing 本体轮廓 + 引脚名/编号两侧标注 + 电源桩/地桩/netport 记号 + 引脚数与间距档说明，图例规范同 `lib/project-docs.md` §7.4/§7.5）；③**画前坐标校正**：图内用数字+直线先画刻度边框核比例尺与本体外接矩形，核对后再补符号细节，补完删刻度（字符画删刻度行列；EDA 试放页临时标尺同理 `sch prim-delete`），校正数据落 `./tmp/design/<工程>-calib-newpart.json`（或 `<型号>-calib-newpart.json`，无工程时以型号为前缀）留痕；④**三图独立**：本文件与 `<工程>-sch-layout.md`、`<工程>-pcb-layout.md` 三份分开维护，互不复制、互不覆盖、互不代替。**用户认可此文件并记决策头（`chain-log add memory --by user`）前禁止建库**。
2. **命令行建立（批准后）**：先 `blocks search` 查可复用块；**先证「库确无此件」**——`lib search`/`lib by-lcsc` 无可用身份才准新建（有库件一律用库件，见 [`../../约束部分/嘉立创元器件库为准/嘉立创元器件库为准.md`](../../约束部分/嘉立创元器件库为准/嘉立创元器件库为准.md)）；无则 `lib symbol create`→`build`（轮廓与引脚按已拍板元件图与手册原理图）、`lib footprint create`→`build`（焊盘形状/编号/间距按手册封装图；官方件不可改，先 `lib footprint copy` 到可写库再 build），最后 `lib device build`/`create` 组装绑定。
3. **数据层验证**：create 自带回读验证；再 `lib footprint get` / `lib symbol get` 逐项对照**已拍板元件图（`./tmp/newpart/<型号>-newpart.md`）**与手册封装图/引脚表——焊盘数、编号、尺寸、丝印层，任一不符回 `build` 重做，不接受「差不多」。
4. **呈现层验证（试放截图）**：新建临时页（`sch page-new`）/临时板（`pcb new-board`）→ `sch place` / `pcb add-component` 试放一件 → `sch export-image` / `pcb snapshot`（stale 切前台重取至 fresh）→ 跑 `python <SKILL_DIR>/scripts/visual-qa.py --schematic --project <工程> --doc <临时页> --artifacts-dir ./tmp/snapshots` 与截图目检（引脚编号朝向、丝印可读、本体对照元件图与手册图；试放件摆放不涉及布局图，**不得改动两份布局文件**）。
5. **判定与清理**：双通道任一不过 = 不算建立完成，回对应 build 修正后重验（重验只改元件图「变更记录」再同步库，布局两图不动）；通过后删除试放件与临时文档（`sch prim-delete`/`page-delete`），验证截图归档 `./tmp/sch/` 并在检查结论登记路径，或整页 `tmp-` 前缀留档不交付。

## 判据与动机

- 三条出路都必须落到「有可核对的手册来源」，不允许在无手册的情况下推进选型。
- **三图独立**：`./tmp/newpart/<型号>-newpart.md`（元件图）、`./tmp/plan/<工程>-sch-layout.md`（原理图布局图）、`./tmp/design/<工程>-pcb-layout.md`（PCB 布局图）各自成文件、各管各的评审与回写，任何一方不得改写或代替另一方。
- **新元件几何唯一依据是该器件技术文档**：`./tmp/datasheet/<型号>.md` 摘要（含页码出处）与 `./tmp/downloads/datasheet/` 原件 PDF 的封装图、引脚表、推荐焊盘；文档没有的尺寸标「未核实」并回第 3 步向用户要手册，不得猜值建库。
- 中断等待期间保持暂停态、不落笔；不替用户默认选择建立新元件或替代方案。
- 用户拒绝全部出路时不静默通过，按中断协议记录原因并交用户拍板。
