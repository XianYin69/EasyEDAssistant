# EasyEDAssistant Reference：低模型优化指南

> 本文件面向参数量较小、指令遵循能力较弱的语言模型（如 GPT-3.5/ Claude-Instant 等），
> 提供「降低出错率、提高执行成功率」的实操建议。高模型可作参考，但不必全照做。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 一、核心原则（低模型易犯错误）

1. **先读后写**：低模型容易「凭记忆补全」而不是回读数据。每步写操作前先跑一遍回读命令，确认现场状态。
2. **命令查真值**：不要凭经验猜 flag——任何不确定的命令先跑 `easyeda <域> --help`，再决定参数。
3. **脚本优先**：重复序列一律走一键脚本（`link-probe.py`/`sch-verify.py`/`pcb-gate.py`/`progress-log.py`），不要手敲多行命令。
4. **失败即停**：脚本退出码非 0 = 当前步骤未完成，不得推进到下一步；宁可报 blocked，不要静默继续。
5. **账本必填**：每步完成必须调 `progress-log.py` 写账目；无账目 ≠ 已完成。

## 二、常见低级错误对照

| 错误表现 | 正确做法 |
|---|---|
| 忘记 cd 到工作区直接跑脚本 | 先确认 `pwd` 不是 skill 目录；用绝对路径 `python <SKILL_DIR>/scripts/xxx.py` |
| 跳步（如直接进 PCB 不跑桥接测试） | 严格按 SKILL.md §1 六步顺序；每步完用 `check-progress.py` 校验 |
| 用 `python3` 在 Windows 上跑 | 统一用 `python`；Windows 上 `python3` 可能不存在 |
| 把产物写到 skill 目录 | 产物一律落工作区 `./tmp/`；脚本有 cwd 守卫会自动拒绝 |
| 把整个 JSON 粘贴到对话里 | 只读 digest 摘要；全文用 `--raw` 另存到 `./tmp/` 并留指针 |
| 遇到报错就猜解法自行推进 | 读 `references/运维与排障/常见错误速查.md` 对照；拿不准转分歧修复稿机制 |

## 三、建议的执行节奏

1. **第一步**：跑 `link-probe.py`，确认链路和 compat 基线，结果落 `./tmp/init/link-probe.json`。
2. **每一步**：先读步骤文档总索引 → 按需读子文件 → 执行 → 跑对应脚本 → 写账目。
3. **卡住时**：停手，读 `常见错误速查.md`；仍不解则开 `./tmp/divergence/` 分歧修复稿移交维护。
4. **每轮循环上限 3 次**：同一问题重试 ≤3 轮仍失败 → 记 `blocked`，转用户拍板，不无限循环。

## 四、低模型友好入口

- `references/运维与排障/常见错误速查.md`（症状→原因→解决 三列速查表）
- `references/嘉立创EDA指令索引/`（按域分类的命令速查，避免瞎猜 flag）
- `references/单步执行/`（续跑场景的标准入口，避免从头重跑浪费额度）
