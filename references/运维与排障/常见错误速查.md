# EasyEDAssistant Reference：常见错误速查手册

> 本文件按「症状 → 原因 → 解决」格式收录高频错误，便于 Agent 与用户在故障时快速定位。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 一、链路/环境类

| 症状 | 原因 | 解决 |
|---|---|---|
| `[link-probe] 两条链路都不通` | EDA 未启动 / MCP 插件未装 / daemon 端口未开 | 先确认 EasyEDA 已打开；再检查插件市场是否已安装 JLCEDA MCP；然后 `easyeda daemon start --auto-update-skill=false`；再重跑 link-probe |
| `[xxx] 拒绝运行：cwd 是 skill 仓库` | 脚本在 skill 目录内运行，产物会污染 skill | `cd` 到用户指定的工程目录再执行（`python <SKILL_DIR>/scripts/xxx.py`） |
| `exit 3: blocked`（门禁） | CLI 不可达 / JSON 解析失败 / 命令参数不对 | 先看 stderr 中的 `[cli] ... -> exit N` 行；用 `easyeda <域> --help` 确认命令存在；不要猜 flag |
| `UnicodeDecodeError` / GBK 崩溃 | Windows 控制台默认 cp936，CLI 输出 UTF-8 中文 | 升级 Python 版本或设 `PYTHONIOENCODING=utf-8`；脚本已加 `errors="replace"` 兜底，遇此报错即为环境问题 |

## 二、流程/门禁类

| 症状 | 原因 | 解决 |
|---|---|---|
| `check-progress 检出缺步骤 N` | 上一步未记账或产物不存在 | 按步骤文档补跑对应命令并落产物，再重跑 `check-progress.py` |
| `visual-qa exit 3: blocking` | 原理图器件越界 / PCB 短路或间距违规 | 读 `./tmp/sch/verify-*.json` 或 `./tmp/pcb/gate-*.json` 中 `failed_or_blocked` 字段定位；改设计后重跑门禁 |
| `compat.drift: true` | 上游 CLI 升级后某 flag/子命令消失 | 按分歧修复稿机制在 `./tmp/divergence/` 建四件套；会话内不阻断，但须在交付报告中如实列出 |
| `version_gate.pin.mismatch: true` | 安装的 connector 版本与钉定快照不符 | 用户手动卸载非钉定版；用 `eext-src.py eext` 取钉定包导入并重启 EDA |

## 三、产物/数据类

| 症状 | 原因 | 解决 |
|---|---|---|
| 截图硬门命中（无新 PNG） | `sch export-image` 未指定 `--format png --out` 或视口冻结 | 确认命令带 `--format png --out <精确路径>`；PCB stale 时经 `doc switch` 切前台重试 |
| `pcb save` 后 `saved:false` | 保存操作未生效（daemon 掉线 / 文件锁定） | 检查 daemon 是否在跑；关闭 EDA 后重开再保存；不要静默跳过 |
| `bom export` / 制造文件导出程序化无入口 | 官方 CLI 未封装 Gerber 导出 | 经 GUI「制造输出」菜单手动导出；程序化通道不在本 skill 覆盖范围 |

## 四、纠错总则

1. 遇未知错误：先看脚本 stderr，再查 `./tmp/` 下的聚合 JSON（`verify-*.json`/`gate-*.json`/`link-probe.json`）。
2. 拿不准是否合规：先读 `references/约束部分/` 对应正本，不要猜。
3. 任何错误不得静默绕过；必须记入 `./tmp/init/progress.md` 并通报用户。
4. skill 本体一字不可改——分歧走 `./tmp/divergence/` 移交维护窗口。
