## 7. 项目文档任务

> 项目级文档任务，不触发版本门禁升级，但仍需 `easyeda health` 确认工程上下文
> （涉及 EDA 数据读取时）；纯本地文件任务可离线执行。

### 7.1 创建许可证（Create License）

- 生成 `LICENSE` / `LICENSE.txt`；默认 **MIT**（与 skill 本身体一致）；
  用户指定时支持 Apache-2.0、GPL-3.0、BSD-3-Clause、CC0。
- 已有 LICENSE 不覆盖，先回读确认；版权年份与主体由用户提供，不猜测。
- 生成后建议同步 `AGENTS.md` 或 README 的许可证声明段；
  提交信息注明 `generate-license`。

### 7.2 生成 README.md

- 内容只来自当前工程回读：概述、BOM 摘要（`bom-enrich.py` 产物）、
  S0–S6/P0–P10 阶段当前门状态、导出路径（gerber/BOM/placement）、许可证引用。
- 已有 README 追加/更新章节，不全量重写；破坏性改写须用户确认。
- `blocked`/`fail` 的门如实标注，不写成通过；图片引用须先 `sch export-image`
  导出官方导图，不用原生视口截图。
- 提交信息注明 `generate-readme`。

### 7.3 块贡献（提交已验证电路到块库）

- 先 `easyeda blocks search` 查重，`blocks show <id>` 读完整 JSON；
  `blocks ls --json` 只有摘要投影，不含全部连接数据。
- 贡献合同：`id/desc/category/source/author`（来源用具体型号手册或官方参考）；
  `parts`（role 表，`part` 指向 standard-parts key）；`internal_nets`
  （≥2 个 ROLE.PIN 引用，同脚只属一网）；`ports`（边界 in/out/bidir）；
  可选 `schematic_layout`（关系形式优先：anchor/flow/attach/pair/orient）/
  `pcb_layout`/`signals`/`silk`/`keepout`。
- 同名多脚全并联写 `J.VBUS*`，不省略后缀让工具猜；引脚引用优先功能名，
  同名脚用真实引脚号。
- 验证：`go test ./internal/blocks/` + `make blocks-audit`；安装态
  `python3 scripts/blocks-pin-audit.py`（离线，无源码时从 CLI 内嵌库逐项取模板）；
  `--probe` 模式清专用空白测量页、放件读脚再清页（须已获准清空该页）。
- `verification` 四项（schematic/component_selection/pcb_drc/bringup）均
  `passed` 且有证据才能设 `production_ready:true`；草稿可贡献但不能声称
  生产验证。

### 7.4 生成 PCB 布局蓝图（Markdown + 字符画边框）

> 在**物理放置/绘制 PCB 之前**，先生成一份 Markdown 布局蓝图，用模块、组件、
> 部件及它们之间的连接把整板布局可视化；板框外形用**字符画（ASCII 边框）**
> 表达。蓝图是规划/评审工件（pre-placement planning artifact），不直接产生
> EDA 图元；须经 P3 中断点（§11.5）用户确认，再驱动 `pcb import-changes`
> 与四档放置（§4.2、§5.5、§5.7）。

**何时生成**：
- 新设计需求→整板：P2（放置）之前生成，作为 P3 板框签核的评审材料。
- 改版/复用布局：重新生成做 before/after 对照（`sch design-diff` 同源）。
- 蓝图是"会改变做法"的选项载体（§6、§11.2）；已在 P3 板框/分区处摊给用户
  拍板，不重复索取许可（§11.4）。

**文件契约**（`<工程>-pcb-layout.md`）：
1. **板框字符画**：用 box-drawing 字符画出板框外形与圆角，标注长宽（mm）、
   安装孔、板边接口开口方向。字符约定：
   - 外框：`╭╮╯╰ ├ ─`（Unicode box）或纯 ASCII `+ - |`；四角圆角用 `╭╮╰╯`。
   - 模块分区：`[模块名]` 或 `+------+` 小框；keepout 区斜线阴影 `////`。
   - 器件：`ref` 缩略（`U1`/`J1`/`C1..C8`/`ANT1`）。
   - 比例尺：声明 1 字符 ≈ N mm（横/纵可不同，按板框长宽取整）。
2. **模块清单**：按 §4.2 九宫格分区（电源左列 / MCU 中列 / RF·IO 右列）
   列出每个功能 Lib 的 bbox、贴边（10 mil）、标题净距。
3. **组件/部件清单**：四档 T1（安装孔）→ T2（板边接口）→ T3（主芯片）→
   T4（卫星件）；每件含 `ref`/`role`/layer(TOP·BOTTOM)/朝向/间距约束（§4.2）。
4. **连接关系**：模块间 / 跨模块 netport 的边集合（net 名 + 起讫器件 +
   线宽档位 + 是否差分/等长/RF）；差分/等长/隔离网成对成组命名（§4.5）。
5. **决策头**：§6 已拍板的 S0 决策（叠层/地域/单双面/焊接工艺）+ 未决项
   （交 §11.5 中断点）。

**字符画示例**（示意；比例尺 1 字符 ≈ 1 mm，板框 40×30 mm）：

```text
╭────────────────────────────────────────╮
│ ┌──────┐   ┌─────────────┐  ┌──────┐ │  顶边 J1(USB) 开口朝上
│ │ PWR  │   │    MCU      │  │ RF   │ │
│ │ U1L1 │   │ U1 Y1 X1 X2 │  │ ANT1 │ │
│ │ C1.. │   │  (ESP32)    │  │ L2C5 │ │
│ └──────┘   └─────────────┘  └─////─┘ │  RF 全层 keepout(////)
│ [电源]    [数字/控制]   [射频]        │
│ ┌──────┐   ┌─────────────┐  ┌──────┐ │  底边 J2 开口朝下
│ │ J1   │   │ 接口/IO TP  │  │ J2   │ │
│ └──────┘   └─────────────┘  └──────┘ │
╰────────────────────────────────────────╯
  40 mm · 安装孔(四角) · 1 字符≈1 mm
```

**生成数据来源**（先读后画，不盲写）：
- `sch connectivity --all-pages`（§5.1）→ 模块/组件/连接真值。
- `pcb list --include-bbox` + `pcb sheet-geometry` → 板框尺寸与分区几何。
- `sch design-diff` / `sch connectivity-diff` → 新旧蓝图 before/after 对照。
- 比例尺/贴边取 §4.2 固定值（贴边 10 mil、标题净距 5 raw）；缺实测
  `sheetBorder` 时注明边界回退（§4.2、§5.1 `sch sheet-geometry`）。

**约束与边界**：
- 蓝图是**规划层**工件（§8.1 验证分层中不属任何硬门）；生成后**不直接**
  驱动写图元——物理放置仍走 `pcb import-changes` + 四档放置 +
  `layout-lint --gate`（§4.2、§5.5、§5.7）。
- 字符画是**示意**；坐标精确值以 `pcb list --include-bbox` 的 `center`
  为准（§3 锚点 vs bbox 中心），字符画不替代 `layout-score`/`pcb check`。
- 连接关系须与 `sch connectivity` pin→net 对账一致；不凭空补连接
  （§4.2 短桩、§4.10 不靠截图推断）。
- 已有蓝图文件追加/更新章节，不全量重写；破坏性改写须用户确认
  （同 §7.2 README 纪律）。提交信息注明 `generate-pcb-layout`。

**与 §11.5 中断点的关系**：蓝图生成完即触发 **P3（板框与安装孔方案）
强制中断点**——把字符画板框 + 分区 + 关键连接摊给用户拍板（单双面/
手焊回流/板框尺寸）；用户批准蓝图后才执行 P2–P10 物理放置。

### 7.5 生成原理图布局蓝图（Markdown + 字符画）

> **原理图也使用画 PCB 蓝图的方法（§7.4）**：在**物理绘制原理图**（`sch compose`
> / `sch apply`，§5.1）**之前**，先生成一份字符画蓝图，**每个模块与组件都用字符画
> 表示**。蓝图是规划/评审工件，不直接产生 EDA 图元；须经 §11.5 **S3（Lib 几何与
> 模块拆分）强制中断点**拍板，批准后才驱动 `compose`/`apply`。

**何时生成**：
- 新设计需求→整板：S3（compose）之前生成，作为模块拆分/页数拍板的评审材料。
- 改版/复用版面：重新生成做 before/after 对照（`sch design-diff` 同源）。
- 蓝图是"会改变做法"的选项载体（§6、§11.2）；已在 S3 摊给用户拍板，
  不重复索取许可（§11.4）。

**文件契约**（`./tmp/plan/<project>-sch-layout.md`，+ 同名 `.json` 骨架）：
1. **纸面/分页字符画外框**：每页一个 box-drawing 外框，标注纸张尺寸（mm）、
   页序号、标题（页名+系统名）。字符约定与 §7.4 一致（`╭╮╯╰ ├ ─` 或 `+ - |`）。
2. **九宫格分区**：按 §4.2 分**电源左列（TL/ML/BL）/ MCU 中列（MC）/
   RF·IO 右列（TR/MR/BR）**；MCU 含 RF 时迁角落，RF pi-network + 天线引到板边。
3. **模块与标题**：每个功能 Lib 一个字符画小框 + 标题行（粉虚线框语义），
   列出框内 `ref` 清单与去耦电容贴邻关系（`C1⌒U1` 记号）。
4. **关键器件字符符号**：`U`=IC、`R`/`C`/`L`、`Y`=晶振、`J`=连接器、
   `ANT`=天线、`IC1`=电源模块、`LED`/`SW`；极性件标 pin-1 朝向箭头。
5. **短桩/netflag/netport 记号**：`P` = 电源桩（朝上）、`⏚` = 地桩（朝下）、
   `>>` = netport（跨模块边界），短桩方向与长度档位按 §4.2。
6. **信号流箭头**：`→` 左→右、`↓` 上→下，主链路单轴、阅读序 Z 字（§12.1）。

**字符画示例**（示意；一页 电源 + MCU + RF 分区，A3 横向）：

```text
╭──────────────────────────────────────────────────────────────╮
│  PAGE 1/2 · 系统主控页 ────────────  297×420mm │
├──────────┬──────────────────────┬───────────────────────┤
│ 电源(TL) │  MCU(MC)             │ RF / IO (TR)          │
│ ┌──────┐ │  ┌──────────────┐   │  ┌─────────────┐     │
│ │ IC1  │ │  │  U1 (ESP32)  │   │  │ ANT1  >>RF  │     │
│ │ P     │ │  │  Y1   X1 X2  │   │  │ L2  C5      │     │
│ └──┬───┘ │  │   C1⌒U1      │   │  └────┬────────┘     │
│   P  ⏚   │  │  >>UART_TX   │   │       >>USB_D+ / D-   │
│ +5V→+3V3 │  │  >>SPI_SCK   │   │  P  ⏚                │
│  [电源]  │  │  [数字/控制] │   │  [射频]   │
└──────────┴──────────────────────┴───────────────────────┘
  P=电源桩(朝上)  ⏚=地桩(朝下)  >>=netport  ⌒=去耦贴邻  →=信号流
```

**生成数据来源**（先读后画，不盲写）：
- `sch connectivity --all-pages`（§5.1）→ 模块/组件/pin→net 真值。
- `easyeda blocks show <id>`（§4.3）→ 块库几何/约束摘要。
- 选型器件引脚表（`standard-parts.json` / `lib by-lcsc`）→ 引脚数与朝向
  （§4.10 先读后画，不凭记忆补脚）。
- 模块间距/贴边取 §4.2 固定值；字符画是**示意**，坐标真值仍以 **5 raw 网格**
  与 `sch compose` 求解为准（§3）。

**约束与边界**：
- 蓝图是**规划层**工件（§8.1 验证分层中不属任何硬门），**不直接写图元**；
  生成后触发 §11.5 **S3** 中断点，用户批准后才 `sch compose` / `sch apply`。
- 已有蓝图文件**追加/更新章节，不全量重写**；破坏性改写须用户确认
  （同 §7.2 README 纪律）。提交信息注明 `generate-sch-layout`。
- 连接关系须与 `sch connectivity` pin→net 对账一致（§4.2 短桩、
  §4.10 不靠截图推断）；net 名与 §4.5"命名即信道"一致。

### 7.6 数字系统逻辑框图（Markdown + 字符画）

> 数字系统的**逻辑**用逻辑框图（字符画）表达，先于原理图进入评审：
> 组合逻辑（门/译码/MUX）、时序逻辑（触发器/锁存/计数器）、有限状态机
> （状态与转移）、总线与握手（地址/数据/valid-ready）、时钟域与复位域。

**字符画记号约定**：
- **IEC 门符号**：`&`(AND)、`≥1`(OR)、`1`(缓冲)、`=1`(XOR)；取反小圈 `o`。
- **MUX**：`]` 梯形简化 + `select` 标注（`S0..S1`）。
- **寄存器/触发器**：`[D Q]`；时钟脚标 `>≡`，复位脚标 `R/o`。
- **状态机**：`S0 --边沿/条件--> S1` 转移表，或环形字符画串联状态。
- **时钟域/复位域**：虚线框 `- - -` 分隔；跨域节点标 **CDC**；复位域跨
  两个时钟域时标 `RESET CDC`。

**示例**（同步复位 + 计数 + MUX 的最小链路示意）：

```text
  CLK ───────────────┐        ┌────────────────┐
                     ▼        │   时钟域 A(- -) │
  nRST ──o─┐         │        │ ┌────┐   ┌──┐  │
           ├───────▶[D Q]────▶│ │ CNT│──▶│ ] │─┼─▶ TX_DATA
           │        │        │ └────┘   │S │  │   ↑ MUX select
  状态机 S0 --tx_valid--> S1 --shift--> S0  │  │
           │        │        │ ┌───┐    └──┘  │
           │        │        │ │ TX │─────────┘
  CDC: S1.tx_valid ─┼────(FIFO 同步)──▶ 时钟域 B(- -)
                    └──────────────────────────────┘
  & ≥1 1 =1 = IEC 门；o = 取反；]> = MUX；[D Q] = 寄存器
```

**文件契约**（`./tmp/design/<project>-logic.md`，+ 同名 `.json`）：
1. **功能清单**：组合/时序/FSM/总线握手/时钟域五项逐项列出。
2. **节点映射表**：节点名 → 实现载体（标准件/块库 IP/可编程逻辑）；
   映射不到的节点显式标 **"未落实"**，不得留空。
3. **状态转移表**：`当前态 --边沿/条件--> 次态 / 输出`；FSM 输出与
   原理图 net 名对齐。
4. **时钟域图**：域划分 + CDC 节点清单（同步器/FIFO 方案）。
5. **决策头**：§6 已拍板项 + 未决项（交 §11.5 中断点）。

**约束与边界**：
- 框图在**方案阶段（S0–S1）**与用户评审（§11.5 中断点），不是绘制阶段
  的附属产物；用户批准后才进 §7.5 蓝图与 §5.1 物理绘制。
- 每个节点必须可映射到**标准件 / 块库 IP / 可编程逻辑**；映射不到的
  标"未落实"并在决策头列为待决项。
- 框图与后续原理图 **net 命名一致**（§4.5 命名即信道），确保 `sch
  connectivity` 可对账；静态判据（时序/协议）见 §7.7。
- **不替代仿真**——是静态评审材料；已有框图追加/更新章节，不全量重写。
  提交信息注明 `generate-logic-diagram`。

### 7.7 静态数据分析与系统可行性评估

> **通过静态数据对整个系统进行分析**：不依赖仿真/实板，仅凭数据手册参数
> 与工程账目在**方案阶段**评估全系统，先判定可行性再进绘制。

**分析项**（至少含）：

| 分析项 | 内容 | 判据来源 |
|---|---|---|
| 功耗/电流预算 | 逐电源轨 `I_total`、峰值、**裕量 ≥30%** | §4.7 电源树与线宽档 |
| 电压域与电平转换 | 域清单 + 转换 IC/2N7002DW 点位 | §4.5 电平匹配 |
| IO/引脚预算 | MCU 引脚占用 vs 需求，含复用冲突 | `sch connectivity` pin 表 |
| 存储/带宽预算 | Flash/RAM、总线速率 vs 采样率 | 手册 + 协议规格 |
| 热耗估算 | LDO `(Vin−Vout)×Iout`；**>0.5W 器件散热判据** | §4.7 / §4.9 |
| 静态时序裕量 | 晶振负载电容计算、RC 复位 `τ=RC` | §4.5 / §4.9 |
| 协议兼容与防护 | 接口兼容矩阵、ESD/TVS 钳位核对 | §4.9 TVS 判据 |
| BOM 成本预算 | 引用 §5.6 浏览器/在线比价缓存 `./tmp/parts/` | 时点数据 |

**计算纪律**：
- 计算过程与中间结果落 `./tmp/calc/`（markdown 推导 + json 数据）；
- 引用数值必须带**手册页码/来源**（§4.10）；未读到的参数标 **"未核实"**，
  不填猜测值、不据此完成选型或改电路。

**结论三档**（写入 `./tmp/design/<project>-feasibility.md`，+ 同名 `.json`）：
- **可行**：所有分析项通过，直接进 S1。
- **有条件可行**：列明条件（改选型/加器件/降指标），条件交用户拍板。
- **不可行**：列冲突项与证据（哪个预算超了、超多少、手册出处）。

**门禁**：
- 结论为 **"不可行"** 或 **条件未被用户接受** 时，不得进入 S1 之后的
  绘制/放置阶段。
- 可行性结论在 **§11.5 S0** 中断点摊给用户拍板（与 §6 决策同批，不重复索取）。
- 提交信息注明 `generate-feasibility`。

### 7.8 生成技术手册与功能手册（工作区根目录交付物）

> **时机**：工作结束时、`./tmp/` 清理（§8.4）**之前**生成。这是最终交付物，
> 落在**工作区根目录**（非 tmp），命名 `<板名/工程名>-technical-manual.md`
> 与 `<板名/工程名>-user-manual.md`。

**内容来源**：只来自当前工程回读 + §7.7 静态分析结果 + 蓝图工件
（**引用其图，不重复绘制**）。

**技术手册**（`<板名/工程名>-technical-manual.md`）：
1. 系统概述与逻辑框图引用（§7.6）。
2. 电源树与静态预算表（§7.7）。
3. 叠层与约束值（差分/等长/keepout，§4.3–§4.7）。
