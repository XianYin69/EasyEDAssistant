# EasyEDAssistant Reference：处理设计问题

> 本文件收录「处理设计问题」步骤的流程（自然语言）。触发时机：检查方案未通过
> （§检查方案及敲定「是否通过所有检查 → 否」）时进入本节。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 流程

1. **先分类**：设计错误/方案缺陷 → 走本流程主线（第 2 步起）；**运行结果与 skill 步骤承诺分歧**（命令/flag/脚本行为/判据与文档不符）→ 同步进入 [`分歧修复稿/分歧修复稿.md`](分歧修复稿/分歧修复稿.md)（`./tmp/divergence/` 四件套：错误说明/分歧记录/修复提示词/临时绕行脚本；**skill 本体不可改**，绕行产出照常过门禁）。
2. 联网搜索可能的解决方案。
3. 将搜索结果呈现，询问用户如何处理该错误。
4. 判断用户是否认可该方案：认可则执行「更改方案」；不认可则跳回第 2 步重新搜索。**同一问题重新搜索并再次征询最多 3 轮**；满 3 轮仍不被认可即停止自动循环，向用户摊牌（用户给出方案 / 登记豁免并记入方案文件 / 调整需求或方案 / 中止本步骤），未获答复保持暂停态、不落笔。
5. 更改方案后，返回被中断的原步骤继续执行。
6. **累计分歧计数**：同一分歧上「正反判断未通过」或「用户否决」每发生一次，`rejection_count` +1 记入 `./tmp/design/<工程>-issue.md` 并 `chain-log.py add memory` 留痕（含 3 轮摊牌后用户持续否决/反复改方案仍未通过的来回；触发场景如用户描述与实现功能不一致、冗余设计）。
7. **达 10 次辩论熔断**：计数到 10 即停止无限来回，转 [`../约束部分/辩论熔断强制方案/辩论熔断强制方案.md`](../约束部分/辩论熔断强制方案/辩论熔断强制方案.md)——建正反双链辩论、合成完整可过门方案并**强制采用**（仅此分歧仅此一次的例外），全程留痕并在交付报告显著标注。
8. **暂停与恢复都记账**：进入摊牌/暂停即 `python <SKILL_DIR>/scripts/progress-log.py --step <被中断步骤号> --name <名> --cmd "处理设计问题: <问题摘要>" --art ./tmp/design/<工程>-issue.md --result blocked`（分歧类在 `--art` 追加 `./tmp/divergence/NN-…/` 目录路径）；用户拍板并处理完成后改记 `pass`。新会话据 `result: blocked` 行识别「上次停在哪、为何停」，不靠对话记忆（见 [`../中断恢复/中断恢复.md`](../中断恢复/中断恢复.md)、[`../单步执行/读取上下文/读取上下文.md`](../单步执行/读取上下文/读取上下文.md)）。

## 判据与动机

- 处理设计问题依赖浏览器工具（`websearch`/`webfetch`），属于运行时知识获取通道，
  但**不豁免「运行环境不可变」**：不得为解决问题而下载插件/可执行体、改 skill 本体或联网查最新版本
  （正本见 [`../约束部分/运行环境不可变/运行环境不可变.md`](../约束部分/运行环境不可变/运行环境不可变.md)；`references/lib/external-resources.md` §13）。
- 更改方案前必须征得用户认可；不被认可则不落地，重新搜索，不自行推进。
