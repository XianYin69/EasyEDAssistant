# EasyEDAssistant Reference：处理设计问题 — 分歧修复稿

> 本文件是「运行结果与 skill 步骤承诺产生分歧」时的处置正本（自然语言）。
> 核心边界：**skill 文件绝对不可改**（[`../../约束部分/运行环境不可变/运行环境不可变.md`](../../约束部分/运行环境不可变/运行环境不可变.md)），
> 但允许且必须在**工作区 `./tmp/divergence/`** 产出修复草稿四件套，供交付移交与维护窗口使用。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 触发判据

1. 满足任一即开分歧目录：skill 步骤文档承诺的命令/flag/产物与实际 CLI 行为不符；`scripts/` 一键脚本报错或输出形状与文档不符；文档判据与 `--help`/`actions` 自描述冲突（cli_compat/compat 探测 drift 常为信号）；判据数值/路径/链接与磁盘实况不符。
2. **不属于**分歧：设计本身错误（走本流程「更改方案」主线）、环境问题（链路不通走桥接排查）。拿不准时按分歧记录同时照常摊牌。

## 四件套规格（目录 `./tmp/divergence/NN-短标题/`，NN 自 01 递增）

3. `00-错误说明.md`：现象原文——触发命令、stdout/stderr 关键段逐字引用、复现步骤、环境上下文（link-probe.json 路径、compat 结果、`easyeda version` 记录、connector 快照 tag）。
4. `10-分歧记录.md`：skill 承诺侧**逐字引用**（文件路径 + 条款号）vs 实际行为侧，差异点列表、影响面（当前步骤/下游哪些检查/是否可用替代路径完成设计）。
5. `20-修复提示词.md`：**维护窗口可直接粘贴执行**的提示词稿——目标 skill 文件精确路径、建议改动内容（含逐字替换文本）、验证方式（check-links/对应一键脚本冒烟）、出处＝本分歧目录。开头必须写明：本稿只是提案，生效唯一通道＝用户把此稿交给维护会话按 RULE_EDIT 执行。
6. `30-repair-<名>.py`：可选——本会话**临时绕行脚本**（如适配变化后的接口再包一层），以工作区为 cwd 运行 `python ./tmp/divergence/NN-…/30-repair-x.py`；文件头注释写明替代哪个 skill 脚本/步骤、失效条件（正本修复即停用）；**不得复制或改名写入 skill 目录**，与 skill 脚本冲突时以 skill 版 + 本目录记录为准。

## 纪律

7. 修复稿不替代用户决策：当前步骤仍走 [`../处理设计问题.md`](../处理设计问题.md) 摊牌/豁免主线；用 30 脚本绕行完成的产出照常过全部机器门禁与截图硬门。
8. **账本挂钩**：开分歧目录时在 `progress-log.py` 账目 `art:` 附上该目录路径；分歧未闭环前不得把该步骤记 `pass`。
9. **移交与免删**：`divergence/` 是交付移交物——交付清理步骤先将其整体移到工作区根 `<工程>-divergence-archive/`（见 [`../../交付与清理/清理/清理.md`](../../交付与清理/清理/清理.md)），不参与 `./tmp/` 删除；交付报告逐条列出（见 [`../../交付与清理/交付报告/交付报告.md`](../../交付与清理/交付报告/交付报告.md) 字段 8）。
10. 新会话/单步执行读取 `./tmp/` 时发现未闭环分歧目录 → 先向用户复述再动工。
11. 禁止外溢：四件套只能写在工作区 `./tmp/divergence/`（及移交后的归档目录）；往 skill 目录写一字即 L3。
