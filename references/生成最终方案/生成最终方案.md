# EasyEDAssistant Reference：生成最终方案

> 本文件收录「检查方案及敲定」末尾生成最终方案的流程（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 流程

1. **汇总结论**：汇集成本及预算检查、元件检查、电气检查、专业技术规范检查的结论，以及系统框图、元件关系图、元件连接图、引脚索引四份图纸。
2. **判定是否全部通过**：有任一检查未通过或存在未证实项 → 不生成最终方案，先走「中断并处理设计问题请求」（见 [`../处理设计问题/处理设计问题.md`](../处理设计问题/处理设计问题.md)）；处理后按 [`../检查方案及敲定/检查方案及敲定.md`](../检查方案及敲定/检查方案及敲定.md) 的判据**只重跑未通过的检查项**，仅当处理导致方案实质变更（选型、拓扑或成本变化）时才回到成本及预算检查与元件检查重算。
3. **提醒用户检查并询问**：全部通过后，提醒用户检查上述结论与图纸，并询问是否愿意生成最终方案。
4. **分支**：
   - 用户同意 → 生成最终方案并结束本流程（落 `./tmp/design/<工程>-final-plan.md`，与「检查方案及敲定」第 3 步账目 `art:`、`单步执行/读取上下文` 读取的方案文件为同一份；交付前的输入基准，随 `./tmp/` 在交付后清理）。
   - 用户不同意 → 回退到「处理用户需求」（见 [`../处理用户需求/处理用户需求.md`](../处理用户需求/处理用户需求.md)）重新澄清需求。

## 判据与动机

- 检查未全部通过时不生成最终方案，避免把不合格方案带进绘制阶段。
- 生成前必须征得用户同意，不同意则回退澄清需求，不代用户拍板。
- 方案落定后任何改动都会使已通过的检查结论失效：须重跑对应检查再定稿。
