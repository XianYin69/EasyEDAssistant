# EasyEDAssistant Reference：桥接联通性测试 — 门禁检查

> 本文件是「桥接联通性测试」第 4 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 检查项

> **脚本化执行（首选）**：第 1、2 项由 `python <SKILL_DIR>/scripts/link-probe.py --project <工程>` 一次跑完，
> 聚合结果落 `./tmp/init/link-probe.json`（`version_gate.verdict` / `health` / `selected_link`），退出码即结论；
> 第 3 项 cwd 确认仍由 Agent 与用户交互完成。下述为判据语义与人工兜底路径。

1. **本机环境自检（会话第一条命令，不联网）**：`easyeda version` 与 `easyeda health`，判据只看 `health` 的 `versionGate`——**CLI 与 daemon 同版、connector 与 CLI 共享 `major.minor` 即 `verdict: ok`**。**禁止** `easyeda update --check`、`--check --exit-code`、`easyeda skill status` 等任何「与 GitHub 最新发行版比较」的行为（正本见 [`../../约束部分/运行环境不可变/运行环境不可变.md`](../../约束部分/运行环境不可变/运行环境不可变.md)）；若 daemon 需启动，必须 `easyeda daemon start --auto-update-skill=false`，否则它会静默覆写已安装 skill 目录。
2. **链路健康**：`easyeda health`（必要时带 `--project <project>`）；daemon 链路要求窗口列表非空、目标工程可枚举；MCP 链路要求工具/资源入口可用。
3. **工作区根目录确认**：询问用户 EDA 工程（原理图/PCB 文件所在目录）的绝对路径，与 Kilocode 会话 `workspace root` 比对；以用户指定路径作为运行时 `cwd`（`./tmp/`、截图、回读 JSON 的落地根）。
4. **只能读不许写**：门禁通过前不执行任何写操作或项目修改。

## 判定与分支

- 三项均通过 → 标记「桥接连通性测试通过」，返回调用方阶段开始绘制（原理图制作第 2 步或 PCB制作第 2 步；同一会话内后续阶段沿用本结论，不重复探测）。
- 链路健康或 cwd 未确认 → 等待 10s 后回到 [`../桥接联通性测试.md`](../桥接联通性测试.md) 第 1 步重新发起，计入同一会话 3 轮重试额度；额度用尽即停止自动重试并转用户摊牌。
- `versionGate.verdict` 非 `ok`（本机组件互不对齐）→ 记 `blocked` 并停止任务，向用户报告版本差异，由用户在其环境内自行升级/替换；**Agent 不得在会话内执行升级**（属维护者编辑期人工动作）。用户处理后**新开会话**从第一条命令重跑。

## 判据与动机

- 自检只比对本机已装组件是否互相对齐，不与最新发行版比较：既满足「运行环境可用」的需要，又不引入运行期自动更新与网络依赖。
- 不得用 `--skip-version-check` 掩盖本机不一致：那是放宽检查而非修复，须如实记 `blocked`。
- cwd 以用户指定为准：与 `workspace root` 不一致时提示确认，避免运行产物落入 skill 目录或错误工程。
- 本机版本不一致会让判据与平台行为错位，属终止性失败，不能靠重试恢复。
