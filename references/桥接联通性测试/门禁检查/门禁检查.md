# EasyEDAssistant Reference：桥接联通性测试 — 门禁检查

> 本文件是「桥接联通性测试」第 4 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 检查项

> **脚本化执行（首选）**：第 1、2、4 项由 `python <SKILL_DIR>/scripts/link-probe.py --project <工程>` 一次跑完，
> 聚合结果落 `./tmp/init/link-probe.json`（`version_gate`（仅记录，`judged:false`）/ `health` / `selected_link` / `compat`），退出码只由链路决定；
> 第 3 项 cwd 确认仍由 Agent 与用户交互完成。下述为判据语义与人工兜底路径。

1. **组件版本记录（会话第一条命令，零联网；**只记录不判定**）**：`easyeda version` 与 `easyeda health` 的 `versionGate` 与本机 connector 快照基线（`python <SKILL_DIR>/scripts/connector-src/eext-src.py report`）一并写入报告备查。**所有检查更新/版本对齐步骤已禁用**（用户指令 2026-09-18）：**禁止** `easyeda update --check`、`--check --exit-code`、`easyeda skill status` 等联网比对行为，也不得因 `versionGate` 非 `ok` 而停止任务（正本见 [`../../约束部分/运行环境不可变/运行环境不可变.md`](../../约束部分/运行环境不可变/运行环境不可变.md)）；若 daemon 需启动，必须 `easyeda daemon start --auto-update-skill=false`，否则它会静默覆写已安装 skill 目录（这是写保护，不属于检查更新）。
2. **链路健康**：`easyeda health`（必要时带 `--project <project>`）；daemon 链路要求窗口列表非空、目标工程可枚举；MCP 链路要求工具/资源入口可用。
3. **工作区根目录确认**：询问用户 EDA 工程（原理图/PCB 文件所在目录）的绝对路径，与 Kilocode 会话 `workspace root` 比对；以用户指定路径作为运行时 `cwd`（`./tmp/`、截图、回读 JSON 的落地根）。
4. **兼容性探针（防上游接口漂移，非更新检查）**：link-probe 对流程依赖的「命令+flag」基线跑 `--help` 自描述探测，结果在 `compat` 字段。`compat.drift` 为真 → **不阻断门禁**（一键脚本已经 `scripts/cli_compat.py` 运行时自适应降级），但 Agent 必须在首次报告中如实列出 `missing_commands` / `missing_flags`，并提示用户在**维护窗口**按 `RULE_EDIT` 修复 skill 文档与基线；运行期禁止改 skill 本体。
5. **只能读不许写**：门禁通过前不执行任何写操作或项目修改。

## 判定与分支

- 第 2、3、5 项通过（第 1、4 项只记录/报告，不判定）→ 标记「桥接连通性测试通过」，返回调用方阶段开始绘制（原理图制作第 2 步或 PCB制作第 2 步；同一会话内后续阶段沿用本结论，不重复探测）。
- 链路健康或 cwd 未确认 → 等待 10s 后回到 [`../桥接联通性测试.md`](../桥接联通性测试.md) 第 1 步重新发起，计入同一会话 3 轮重试额度；额度用尽即停止自动重试并转用户摊牌。
- 运行中若出现疑似组件互不对齐引发的行为异常（报错模式与快照源码/`compat` 基线不符）→ 如实报告版本记录与异常证据，建议用户在维护窗口自行对齐组件后新开会话；**Agent 全程不得执行升级或联网查版本**。

## 判据与动机

- 检查更新/版本门禁全面禁用：一次实测证明「版本判定」本身会成为工作流断点（健康机器被 versionGate 解析问题误判 blocked），且修复渠道（升级）恰被运行环境不可变禁止——两害相权，改为「链路可用即放行 + 漂移 compat 早发现 + 行为差异对照本地 connector 源码快照离线解释」。
- `--skip-version-check` 同样禁止使用：现在没有任何合法场景需要它（版本判定已不存在），出现即属异常，须报告。
- cwd 以用户指定为准：与 `workspace root` 不一致时提示确认，避免运行产物落入 skill 目录或错误工程。
- 组件真实不兼容导致的失败会以「运行报错」形式暴露，由失败分支（处理设计问题/桥接排查环）兜住，不再靠启动前预判。
