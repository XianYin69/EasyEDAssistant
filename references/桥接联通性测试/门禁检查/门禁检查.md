# EasyEDAssistant Reference：桥接联通性测试 — 门禁检查

> 本文件是「桥接联通性测试」第 4 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 检查项

1. **版本门禁（会话第一条命令）**：`easyeda update --check --exit-code`，先于任何项目读取、离线规划、`health` 与 EDA 操作。CLI/Skill/daemon 必须精确等于 GitHub latest；Connector 与 latest 共享 `major.minor` 兼容线；仅 patch 差异可通过。
2. **链路健康**：`easyeda health --project <project>`；daemon 链路要求窗口列表非空、目标工程可枚举；MCP 链路要求工具/资源入口可用。
3. **工作区根目录确认**：询问用户 EDA 工程（原理图/PCB 文件所在目录）的绝对路径，与 Kilocode 会话 `workspace root` 比对；以用户指定路径作为运行时 `cwd`（`./tmp/`、截图、回读 JSON 的落地根）。
4. **只能读不许写**：门禁通过前不执行任何写操作或项目修改。

## 判定与分支

- 三项均通过 → 标记「桥接连通性测试通过」，进入原理图制作。
- 链路健康或 cwd 未确认 → 等待 10s 后回到 [`../桥接联通性测试.md`](../桥接联通性测试.md) 第 1 步重新发起，计入同一会话 3 轮重试额度；额度用尽即停止自动重试并转用户摊牌。
- 版本门禁返回非 0 → 停止任务，按 [`../../../Sample/easyeda-agent/references/environment-setup.md`](../../../Sample/easyeda-agent/references/environment-setup.md) 升级；升级或替换组件后**必须新开会话**，从第一条命令重新开始。

## 判据与动机

- 门禁不得绕过：`--version`、`--preserve`、`--skip-version-check` 或仅看 `health` 都不算通过。
- cwd 以用户指定为准：与 `workspace root` 不一致时提示确认，避免运行产物落入 skill 目录或错误工程。
- 版本不一致会让后续判据与平台行为错位，属终止性失败，不能靠重试恢复。
