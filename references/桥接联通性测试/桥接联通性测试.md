## 流程

1. **发起 MCP 端口访问请求**：探测 `http://127.0.0.1:7655/mcp`（JLCEDA MCP 插件 HTTP 端点；同插件另有桥接端点 `ws://127.0.0.1:8765/bridge/ws`）。
2. **判定链路**：
   - 可访问 JLCEDA MCP 插件接口 → 全程使用 MCP，进入第 4 步门禁检查。
   - 不可访问 → 探测 EasyEDA Agent 插件端口 `60832`（CLI/daemon 链路）；可访问 → 全程使用 CLI/daemon，进入第 4 步。
   - 两者都不可访问 → 进入第 3 步排查。
3. **询问用户排查**（见 [`端口探测与插件确认/端口探测与插件确认.md`](端口探测与插件确认/端口探测与插件确认.md)）：依次确认两个插件是否安装、嘉立创 EDA 是否打开；均否时提示安装嘉立创 EDA 及这两个插件，用户确认已安装或已打开则等待 10s 后回到第 1 步重试。
4. **门禁检查**（见 [`门禁检查/门禁检查.md`](门禁检查/门禁检查.md)）：执行链路健康检查、版本门禁与工作区根目录（cwd）确认。
5. **判定门禁**：通过 → 标记「桥接连通性测试通过」；不通过 → 等待 10s 后回到第 1 步重新发起。

## 判据与动机

- MCP（7655）与 CLI/daemon（60832）是替代关系，不是级联备用：一旦某条链路连通即全程使用，不重试另一条、不做多余检测。
- 重试统一等待 10s，不循环刷新、不批量杀进程、不重发写操作、不清空 IndexedDB。
- 版本门禁非 0 属终止性失败（须按环境配置升级并新开会话），不属「等待 10s 重试」的暂态故障。
