## 流程

> **脚本化执行（首选）**：重复交互已封装为 [`../../scripts/link-probe.py`](../../scripts/link-probe.py)——**以工作区为 cwd** 运行 `python scripts/link-probe.py [--project <工程>]`，一次完成第 1、2、4 步（探 MCP 7655/桥接 8765 → 探 daemon 60832-60841 → `update --check --exit-code` → `health --json` → 按正本 §1.1 选定链路），结果落 `./tmp/init/link-probe.json`。**退出码即门禁结论：0 选定且门禁过 / 2 版本无法确认（不阻断，报告标注）/ 3 版本门禁未过或两链路都不通（终止/进排查）**。cwd 落在 skill 仓库时脚本直接拒跑（产物防污染）。下述步骤为判据的人工等价描述与失败排查路径。

1. **发起 MCP 端口访问请求**：探测 `http://127.0.0.1:7655/mcp`（JLCEDA MCP 插件 HTTP 端点；同插件另有桥接端点 `ws://127.0.0.1:8765/bridge/ws`）。
2. **判定链路**：
   - 可访问 JLCEDA MCP 插件接口 → 再探测 `60832`：daemon 也连通 → **优先全程使用 CLI/daemon**（批量写少往返、开销低），进入第 4 步门禁检查；仅 MCP 连通 → 全程使用 MCP，进入第 4 步。
   - 不可访问 → 探测 EasyEDA Agent 插件端口 `60832`（CLI/daemon 链路）；可访问 → 全程使用 CLI/daemon，进入第 4 步。
   - 两者都不可访问 → 进入第 3 步排查。
3. **询问用户排查**（见 [`端口探测与插件确认/端口探测与插件确认.md`](端口探测与插件确认/端口探测与插件确认.md)）：依次确认两个插件是否安装、嘉立创 EDA 是否打开；均否时提示安装嘉立创 EDA 及这两个插件，用户确认已安装或已打开则等待 10s 后回到第 1 步重试。
4. **门禁检查**（见 [`门禁检查/门禁检查.md`](门禁检查/门禁检查.md)）：执行链路健康检查、版本门禁与工作区根目录（cwd）确认。
5. **判定门禁**：通过 → 标记「桥接连通性测试通过」，回到调用方阶段（原理图制作或 PCB制作的下一步）；不通过 → **版本门禁返回非 0 属终止性失败，直接按子文件分支处置（升级+新开会话），不进入重试环**；其余失败（链路健康 / cwd 未确认）等待 10s 后回到第 1 步重新发起，本次测试最多重试 3 轮（额度随每次完整桥接测试重计；后续阶段沿用通过结论时不再消耗）；第 3 轮仍不通过即停止自动重试，向用户摊牌（继续重试 / 改用另一条链路 / 检查插件安装与 EDA 打开状态 / 中止任务），未获答复保持暂停态、不落笔。

## 判据与动机

- MCP（7655）与 CLI/daemon（60832）是替代关系，不是级联备用：一旦某条链路连通即全程使用，不重试另一条、不做多余检测；两条都连通时**优先 CLI/daemon**——批量与写路径一次派发一轮往返，token 开销显著低于逐次 MCP 调用。
- 重试统一等待 10s，不循环刷新、不批量杀进程、不重发写操作、不清空 IndexedDB。
- 版本门禁非 0 属终止性失败（须按环境配置升级并新开会话），不属「等待 10s 重试」的暂态故障。
