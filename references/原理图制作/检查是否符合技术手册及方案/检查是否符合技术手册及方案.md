# EasyEDAssistant Reference：原理图制作 — 检查是否符合技术手册及方案

> 本文件是「原理图制作」第 3 步的分支细则（自然语言）。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 检查项

1. **器件与手册一致**：`sch list --all-pages --include-device-identity` 回读工程中每个器件的位号、MPN、封装，与 [`../../元件检查/封装与引脚检查/封装与引脚检查.md`](../../元件检查/封装与引脚检查/封装与引脚检查.md) 建立的手册出处逐项对照（MPN、封装型号、引脚数与引脚名）；对照记录落 `./tmp/sch/` 检查结论文件。
2. **连接与方案一致**：`sch connectivity --all-pages` 回读的 pin→net 与 [`../../引脚索引/引脚索引.md`](../../引脚索引/引脚索引.md) 的黄金表、[`../../元件连接图/元件连接图.md`](../../元件连接图/元件连接图.md) 的连接图逐条对账；NC 必须与方案一致。
3. **模块与图纸一致**：`doc ls` 分页清单 + `sch sheet-geometry` 图框与 [`../../系统框图/系统框图.md`](../../系统框图/系统框图.md)、[`../../元件关系图/元件关系图.md`](../../元件关系图/元件关系图.md) 的归属一致（元件所属页/模块 = 关系图归属）；不用截图推断连接。
4. **门禁复核**：`python <SKILL_DIR>/scripts/sch-verify.py --project <工程>`（内含逐页 `sch gate --strict` 四联：`layout-lint → check → bridge-check → SDK DRC`，聚合落 `./tmp/sch/verify-*.json`）；退出码 0 且 `pass` 才算通过，`fail` 是设计问题，`blocked`（非 0/链路异常）是检查未完成。

## 判定与分支

- 全部检查项一致 → 判定「符合」，进入保存交付（回总索引第 4 步）。
- 任一项不符 → 判定「不符合」，回到 [`../../绘制原理图/绘制原理图.md`](../../绘制原理图/绘制原理图.md) 修改后重跑本检查（同一部分整步回退最多 3 轮，满轮转 [`../../处理设计问题/处理设计问题.md`](../../处理设计问题/处理设计问题.md) 摊牌）。
- 命令报错 / `sch gate` 返回 `blocked` / 链路或环境异常 → 判「检查未完成（blocked）」，**先回 [`../../桥接联通性测试/桥接联通性测试.md`](../../桥接联通性测试/桥接联通性测试.md) 修环境再重跑**，不得把 blocked 当作设计 fail 回退重画，也不得当作通过放行。

## 判据与动机

- 以数据回读为权威，截图只做视觉终检；两者不一致时以回读数据为准并把 stale 标为阻断项。
- 「封装/引脚与手册不符」属元件级问题，须回到元件检查流程处理，不在此处就地改封装。
- 不得只凭 `0 fatal` 宣称全部通过：官方 DRC 可能返回聚合数，INFO/WARN 须单列。
