# EasyEDAssistant Reference：约束 — 运行环境不可变

> 本文件是「设计执行期运行环境不可变」的正本（自然语言）：skill 本体只读、禁下载可执行与 EDA 插件、禁查最新版本。
> 编辑遵守 RULE_EDIT.md：文本 ≤ 50 行、自然语言。

## 一、skill 本体只读（禁止运行期自我更新）

1. 设计执行期**禁止任何改写 skill 目录组件的行为**：不得执行 `easyeda skill sync`、`easyeda skill status`、`easyeda update`（含 `--skill-only`）、`easyeda update --version/--local-dir`，也不得用 `write`/`edit`/复制等方式改动 `SKILL.md`、`references/`、`scripts/`、`agents/`、`Sample/`、`CHANGELOG.md`（那些改动只能由人按 [`../../../RULE_EDIT.md`](../../../RULE_EDIT.md) 在编辑期做）。
2. **启动 daemon 必须显式关闭技能自同步**：`easyeda daemon start --auto-update-skill=false`，并建议设 `EASYEDA_SKILL_PRESERVE=1`。daemon 的 `--auto-update-skill` **默认为 on**，启动时会静默覆写已安装的 skill 目录（`~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills`）——这是运行期改 skill 的主要通道，不加该参数即违规。
3. 发现 skill 目录被外部改写（版本或内容突变、出现非本次编辑的 diff）→ 立即停止任务、保留现场并报告用户，不得就地续跑或自行恢复。

## 二、禁下载可执行文件与 EDA 插件

4. 禁止下载或落地任何可执行体与 EDA 插件包：`.exe` `.dll` `.so` `.dylib` `.bin` `.com`、脚本 `.sh` `.ps1` `.bat` `.cmd` `.vbs` `.js` `.jar`、归档 `.zip` `.rar` `.7z` `.tar` `.gz` 等，以及 **EDA 插件/扩展包 `.eext`**（含任何 marketplace/侧载扩展、`.esmt`、插件清单包）。
5. 唯一取物通道是 `python <SKILL_DIR>/scripts/net-download.py`，其黑名单为权威拦截点；**没有任何参数能越过格式判定**（无 `--force`、也无 `--yes`）。用户手工提供的插件包也不得由 Agent 安装或导入 EDA。
6. 需要插件/新能力时只能**报告并请用户在其环境外自行安装**，安装动作不属于本 skill 的设计执行期。

## 三、禁查最新版本（环境自检只比对本机）

7. 禁止任何「与最新发行版比较」的行为：不跑 `easyeda update --check`、`easyeda update --check --exit-code`、`easyeda skill status`（其语义即"installed vs latest release"），不访问 GitHub Release 比版本。原「会话第一条命令 = 版本门禁」的硬门就此废止。
8. 替代为**本机不联网自检**（会话开始时一次）：`python <SKILL_DIR>/scripts/link-probe.py`——内部只跑 `easyeda version` 与 `easyeda health`，判定标准是 health 的 `versionGate`（已含 CLI/daemon/connector 版本）：**CLI / daemon 同版、connector 与 CLI 共享 major.minor 即 `verdict: ok`**，全程不比较 latest。
9. 自检不一致（`verdict` 非 ok）→ 记 `blocked` 并转用户处理（升级属维护者编辑期人工动作，不由 Agent 在会话内执行）；`health` 报错/不可达同样按 blocked 处理，不猜通过。

## 违规后果

- 运行期改 skill 组件、启动 daemon 未带 `--auto-update-skill=false`、下载可执行/`.eext`、查 latest 版本 → [`../处罚机制/处罚机制.md`](../处罚机制/处罚机制.md) **L3**：停止任务、恢复环境原状、在交付报告中通报。
- 同一会话重复发生 → **L4** 收回授权。
