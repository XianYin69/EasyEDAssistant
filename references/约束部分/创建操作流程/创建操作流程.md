# EasyEDAssistant Reference：约束 — 创建操作流程

> 本文件是「新建文件 / 文件夹的标准操作流程」正本（自然语言），由 `FILE_CREATION_POLICY.md` v2.0 迁入。

## 约束条款（标准流程）

1. **需求分析**：确认是否真的需要新文件或新目录，是否落在允许范围内（[`../文件与文件夹创建范围/文件与文件夹创建范围.md`](../文件与文件夹创建范围/文件与文件夹创建范围.md)），是否已有权限。
2. **方案设计**：拟定结构与路径、确定格式与命名、决定版本控制策略（入库还是 `.gitignore`），并记录本次变更需求。
3. **审批**：新增脚本须安全审核；重大结构变更（新增功能子目录、放宽白名单、覆盖既有交付物）须项目负责人或用户批准；文档改动走评审与 `CHANGELOG.md` 记录。
4. **创建**：用 `write`/`edit` 落文件；目录通过文件路径间接创建；确认权限设置不低于项目要求、不放宽执行位。
5. **验证与审核**：核对内容合规、路径正确、命名可辨、无遗留临时或不必要文件；工作产物核对确实落在工作区 `./tmp/`。
6. **版本控制**：临时与运行产物进 `.gitignore`；正常文档提交 git；提交前看 `git status` 与 diff，只暂存本次意图文件。

## 特殊情况

- **紧急修复**：允许先创建临时文件解决严重问题，但修复后必须立即清理并在报告中注明。
- **文档更新**：遵循既有结构与编号，不随意增删章节层级；已有正本不复制第二份，改指针即可。
- **脚本修改**：在不破坏原有功能的前提下修改，不顺手重构结构；格式白名单变更须同步策略文件与脚本常量两处。
- **skill 本体编辑**：改 `SKILL.md`/`references/`/`CHANGELOG.md` 等遵守 [`../../../RULE_EDIT.md`](../../../RULE_EDIT.md) §二（先问预留部分、判断是否拆分、改 CHANGELOG、提交 git）。

## 违规后果

- 跳过审批或验证直接落盘 → 按 [`../处罚机制/处罚机制.md`](../处罚机制/处罚机制.md) L2 回退重做；造成仓库污染 → L3。
