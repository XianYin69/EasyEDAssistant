# EasyEDAssistant Reference：约束 — 文件命名规范

## 约束条款

1. **用途可辨**：文件名必须以项目用途命名，能从名字看出「是什么、属于哪个工程/器件」；禁止 `new.md`、`test.txt`、`tmp1.json`、`final2.md` 这类随机或模糊名。
2. **范围匹配**：不得使用超出当前任务范畴的名称（个人笔记、试验、临时草稿类命名一律禁止入库）。
3. **运行工件命名式**：沿用既有式样——设计基线 `<工程>-pcb-spec.md`、原理图蓝图 `<工程>-sch-layout.md`、逻辑框图 `<工程>-logic.md`、可行性 `<工程>-feasibility.md`、学习笔记 `<topic>.md`、截图 `step-<索引>-<时间戳>.png`、下载审计 `index.json`。
4. **交付物命名式**：工作区根目录手册为 `<板名>-technical-manual.md` 与 `<板名>-user-manual.md`。
5. **步骤文档命名式**：`references/<步骤>/<步骤>.md` 为主文档；子文件与其所在子文件夹同名（总索引 + 子文件同名约定）。
6. **数据手册**：保留厂商原始文件名（清洗掉路径分隔符与非法字符后），不改写型号，便于反查出处。
7. **提交信息**：按 `<type>(<scope>): <摘要>`（`feat(refs)` / `docs(refs)` 等）；生成类工件沿用 `generate-sch-layout`、`generate-pcb-layout`、`generate-logic-diagram`、`generate-feasibility`、`generate-manuals` 关键词。

## 违规后果

- 命名不可辨或超范畴 → 立即停止该写入并改名，或撤销该文件；已入库的按 [`../处罚机制/处罚机制.md`](../处罚机制/处罚机制.md) L1 处理。
- 工件名与契约式样不符（如截图无时间戳） → 重命名后重新登记，不得引用旧名文件作结论依据。
