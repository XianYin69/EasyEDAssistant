# EasyEDAssistant Reference：约束 — 文件存储格式

## 约束条款

1. **总则**：技术文件与数据手册可用 markdown 或 pdf；除此以外的文档一律 markdown，不引入第三种文档格式。
2. **技术文件（markdown）**：方案文件、设计基线、检查结论、蓝图与逻辑框图、可行性结论、学习笔记、交付报告、手册说明、各步骤规范文档，全部 markdown。
3. **数据手册（markdown 或 pdf）**：手册原件可为 pdf（仅出现在数据手册与标准文档语境，如 `./tmp/downloads/datasheet/`、`docs/`）；其摘要与参数引用必须另写 markdown 并标注页码出处。
4. **禁用文档格式**：不得用 `.txt`、`.log`、`.docx`、`.rtf`、`.odt`、`.html`、pdf 承载设计文档、方案、结论或说明正文。
5. **机器工件不算文档**：回读 JSON、截图 PNG、Gerber/Excellon、坐标文件、EDA 原生库文件（`.sch`/`.pcb`/`.elib` 等）按 `./tmp/` 目录契约存放，只作数据与图像，不充当人读文档；其含义由同名或关联 markdown 说明。
6. **入库白名单**：仓库（skill 目录）内文档只允许 `.md`；`scripts/` 放 `.py`，`Sample/easyeda-agent/` 放 `.md`/`.json`，`agents/` 放 `.yaml`/`.json`；下载白/黑名单以策略文件为准，不因「看似必需」放开。
7. **两处一致**：格式判定同时存在于策略文件与脚本常量，改一处必须同步另一处，不一致时以策略文件为准。

## 违规后果

- 以禁用格式落文档 → 转换为 markdown 或删除；用 pdf 写正文 → 改为 markdown 正文并只保留手册原件。
- 试图绕过格式门禁（伪造扩展名、解压夹带、请求 `--force`）→ 按 [`../处罚机制/处罚机制.md`](../处罚机制/处罚机制.md) L3 停止并通报。
