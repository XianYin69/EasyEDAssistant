# EasyEDAssistant Reference：约束 — 上下文存储压缩机制

> 压缩的目标是「少载入、少重复、少膨胀」，底线是「不丢证据链」。

## 约束条款

1. **文档层压缩**：单文件 ≤ 50 行；超长按 RULE_EDIT「总索引 + 子文件」拆分，先读总索引再按需读子文件，不整目录通读。
2. **主干分层**：SKILL.md 只留流程入口与路由，细则下沉 `references/`；`references/lib/` 为维护者文档，不作为运行时真值加载。
3. **按需加载**：按当前任务只加载相关子域判据（如某电气子域或公式文件），无关子域不读入。
4. **工件代替叙述**：大体积回读结果（connectivity、list、drc、report）一律 `> ./tmp/<契约子目录>/<名>.json` 落盘，上下文只留统计行（如器件数/网络数/告警数）与文件路径，不把整份 JSON 贴入对话；推导与结论分文件存放、互相引用。
5. **数量与体积上限**：快照类只保留最近 3 张；下载单文件上限按策略执行，超限不留半成品；重复内容以引用替代复制（手册引页码、蓝图引路径、基线引文件名）。
6. **续跑压缩**：非首次设计先读 `./tmp/init/` 与相关上下文文件恢复状态，从被中断点继续，不重跑已通过阶段、不重述已拍板决策。
7. **不可压缩项**：出处三要素、门禁结果、未运行检查与 WARN 清单、用户拍板记录，任何为省上下文做的省略都必须保留可反查路径（文件 + 页码或命令）。
8. **缓存友好前缀稳定（性能判据）**：推理侧 prompt 缓存按前缀匹配，前缀任何改写使后续全部失效——SKILL.md 主干与路由表在会话内保持静态、细则变更走文末追加或子文件；tmp 上下文与逻辑链文件同样只增不改；按需加载的子域文档以消息注入，不回写主干。

## 违规后果

- 超行未拆分、整份 JSON 入对话、通读无关子域 → L1 改正（拆分或改为落盘引用）。
- 为省上下文删掉出处或隐瞒未运行检查 → 按 [`../处罚机制/处罚机制.md`](../处罚机制/处罚机制.md) L2–L3 处理。
